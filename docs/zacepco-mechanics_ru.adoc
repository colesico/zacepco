== О документе

Документ описывает механику детективной игры, задаёт общие правила, по которым она должна строиться.  
Для целостности игры неотъемлемым дополнением к этой механике являются *сценарии преступления*, которые описывают сюжетную составляющую.  
Сама механика, по сути, является *фреймворком* дедуктивной детективной игры с элементами случайности.

== Сценарий преступления

Сценарий в рамках механики описывает преступление, которое *уже произошло*.  
В процессе игры игроки (детективы) должны раскрыть это преступление.  
Сценарий ориентируется на разную степень сложности раскрытия преступления, описывая, например, одно преступление или сразу несколько, с участием одного или нескольких преступников, с наличием или отсутствием сообщников, с разным количеством подозреваемых, длительностью преступления, размером «театра действий» и т. п.

Любой сценарий содержит:

* Инструкции для подготовки к началу расследования.
* Информацию для хода расследования.
* Раздел «Ответы», который можно посмотреть в конце игры.

Готовые сценарии идут с игрой либо же генерируются специальной программой.

Игра происходит по выбранному игроками сценарию и делится на две *фазы*.

В первой фазе игроки согласно сценарию выполняют подготовительные действия для начала расследования: сборку игрового поля и др. 
Эта фаза, по сути, воссоздаёт для игроков начальную картину совершённого преступления.

Вторая фаза — расследование, кооперативный процесс раскрытия преступления детективами.

В конце игры выводы следствия сравниваются с ответами из сценария.

== Мастер-программа

Для модерации процесса игры используется компьютерная программа — *«Мастер-программа»*, которая настраивается сценарием под конкретную игру.  
Программа также автоматизирует все расчёты, связанные с игровым процессом, и контролирует игровые механики.

== Игровые сущности и связи

Сценарий оперирует следующими типами *игровых сущностей*:

* *Персонаж ( P )* — действующее лицо в преступлении (personage);
* *Локация ( L )* — часть места преступления (location);
* *Улика ( C )* — часть информации о преступлении (clue);
* *Время ( T )* — момент времени в течение преступления (tick).

Сами игровые сущности (кроме времени) представлены карточками сущностей.  
Каждая такая карточка в зависимости от типа сущности имеет свой формат.  
Сущность идентифицируется уникальным идентификатором, начинающимся с 
буквы, которая соответствует типу сущности, и далее уникального кода сущности. 

====
Например, P2, LLIB, CKEY.
====

Время не имеет собственных карт, только порядковый номер (T1, T2, …) и привязку ко времени.

Каждая из игровых сущностей может быть связана сценарием с любыми другими сущностями.  
С точки зрения связи, когда одна сущность ссылается на другую, первая называется *ключевой сущностью*, а вторая — *целевой сущностью*.

Сценарий задаёт совокупность игровых сущностей и их связей, что, по сути, описывает преступление (определяет модель преступления).

Часть из этих сущностей и связей может не относиться к преступлению и служить для усложнения процесса расследования (ложные улики).

Перед началом расследования детективам известна некоторая небольшая часть сущностей и их связей.  
В процессе расследования детективы постепенно открывают остальные сущности и связи.

Механика в общем случае предполагает, что карточки сущностей требуют самостоятельного изготовления (печати) перед игрой. 
Мастер-программа может сгенерировать их макеты для печати из сценария. 

Печатать все карточки не обязательно, часть карточек в сценарии может быть заимствована из других сценариев. Такие карточки называются *референсными*, сценарий содержит пометки, из каких сценариев могут быть взяты эти карточки.


== Открытие сущностей и связей

В игре используется механика *поэтапного* открытия детективами карт сущностей и обнаружения связей между ними.

Детективы на основе некоторых уже открытых ключевых сущностей могут узнать их связи с другими целевыми сущностями, как открытыми, так и ещё не открытыми.  
Потом выбрать другие ключевые сущности и по ним снова определить очередные целевые сущности и связи, и так далее.

Связи сущностей выявляются через *открытие* улик. 
Способ открытия определённых улик сценарий задаёт в виде конкретной игровой механики.

Чтобы не раскрыть перед детективами сразу всю информацию о преступлении, для поэтапной выдачи информации используется *мастер-программа*.

Дайс D12.

== Ресурс, очки

В игре каждое действие детектива стоит определённого *ресурса*.  
В случае успешности действия игроку начисляются *очки*.  
Сценарий определяет общий *бюджет* ресурса на расследование.  
При исчерпании бюджета расследование останавливается, детективы должны сделать выводы по имеющимся данным и сравнить результаты с ответами сценария.

При инициализации расследования в мастер-программе игроки могут увеличить или уменьшить начальный бюджет на определённый процент, обеспечив себе дополнительное преимущество или усложнение.

Индивидуальное количество заработанных очков определяет лучшего детектива в расследовании, при условии, что детективы раскрыли преступление. Если детективы не смогли раскрыть преступление, заработанные очки не учитываются.

== Игровое время

Сценарий преступления охватывает промежуток времени, разделённый на *такты* (`T1, T2, … Tn`) — равные или неравные интервалы времени.

Каждый такт имеет метку времени (даты-времени), например `T4 = 21:30`. Метка задаёт *правую границу* такта. События `T4` происходят после метки предыдущего такта и не позднее `21:30`. Сценарий содержит общедоступную таблицу «Таймлайн» (timeline), в которой каждому такту присвоена метка времени.
Разница между соседними метками должна быть правдоподобной: за такт персонаж должен успеть выполнить действия, подразумеваемые сценарием.

Все значимые события преступления происходят в определённые такты, привязка улик осуществляется к временным меткам тактов, а не к значениям времени внутри самого такта. Даже, например, если для T3 = 21:00, T4 = 21:30, в улике указано время 21:20 — считается, что событие произошло в такт T4, и неважно, когда именно внутри такта. Точный порядок событий внутри такта не определён и не используется для дедукции, т. е. все события внутри такта являются согласованными с точки зрения улик.

Чем больше тактов, тем сложнее раскрыть преступление.

== Место преступления, локации, связи

В сценарии место преступления определяется в виде графа.  
В фазе подготовки к расследованию игроки на основе этого графа из отдельных *локаций* (location) — узлов графа — собирают место преступления — сцену (scene). Сцена представляет собой сетку определённого размера. Размер сетки задаётся сценарием. В любую ячейку сетки сцены помещается локация. Некоторые ячейки сцены могут быть оставлены пустыми.

Каждая локация представлена квадратной карточкой локации (референсной или кастомной). Карточка локации содержит следующую информацию:

* ID;
* Название;
* Описание;
* Изображение локации.

Две смежные локации могут соединяться между собой *путями* (way), определяющими возможность перемещения между ними персонажа.  
Если требуется соединить две несмежные локации, используются карточки путей с разной конфигурацией (прямой, поворот), которые выкладываются друг за другом в пустые ячейки сцены, соединяя нужные локации.  
Путь всегда соединяет только две локации. Две локации могут быть соединены только одним путём.

В сценарии для перемещения по пути можно в виде *описания* задать какие-либо ограничения или характеристики пути. Например: река, шириной 10 метров. Если описание пути отсутствует, считается, что для расследования важен только сам факт возможности перемещения из одной локации в другую и не важны условия для этого перемещения.

На самом пути с персонажами никогда ничего не происходит,  
если нужно смоделировать какие-либо действия персонажа в пути, то путь заменяется полноценной локацией.

Сценарий также может предполагать наличие *«скрытых»* (hidden) путей между локациями, которые изначально не видны детективам.  
О существовании таких путей детективы узнают в процессе расследования.  
При открытии улики, раскрывающей скрытый путь, на сцену также выкладывается карточка этого пути.

Скрытый путь может вести в *скрытую локацию*.  
Это такая локация, о которой детективы не знают до начала расследования.  
При открытии улики, которая раскрывает *скрытый путь и скрытую локацию*, на сцену выкладывается карта скрытой локации в указанное в сценарии место и путь к ней.
После открытия локация становится доступной для следственных действий.

Информация обо всех скрытых путях и локациях доступна в *ответах* сценария.

При разработке сценария локации и описания путей должны определяться таким образом, чтобы учитывался их смысл в расследовании.  
Например, в пещере может не быть света, в подвал персонаж может войти только с ключом, в оранжерее может расти ядовитое растение, бар работает с 3-го по 6-й такт и др.  
Смысловая нагрузка и описание локаций и путей должны помогать детективам в расследовании.

Сценарий для каждой локации описывает журнал событий (log) этой локации для каждого такта времени.  
В событии лога содержится информация о том, для каких персонажей эта локация была *целевой* в такте, какие улики появились в локации.

Журнал событий используется в конце игры в качестве ответов при проверке выводов следствия и недоступен игрокам в процессе следствия.

== Персонажи

Действующее лицо в преступлении — это *персонаж* (personage).  
Каждый персонаж представлен (референсной или кастомной) карточкой персонажа.  
Карточка персонажа содержит следующую информацию:

* ID;
* Имя;
* Досье (описание);
* Изображение персонажа.

Набор персонажей в игре определяется сценарием.  
Сценарий задаёт явных персонажей — они известны перед началом расследования.  
Их карты выкладываются рядом с игровым полем.

Сценарий также может использовать *скрытых персонажей*.  
Скрытый персонаж — один из тех, чья карта ещё не выложена из колоды персонажей в открытую на стол.  

Определить наличие скрытого персонажа можно в процессе расследования логически, на основе обнаруженных улик, либо же при открытии улики, раскрывающей скрытого персонажа (аналогично уликам, указывающим на скрытый путь или локацию).  
При обнаружении улики, раскрывающей скрытого персонажа, его карта выкладывается в открытую рядом с игровым полем к картам остальных персонажей.  
После этого персонаж становится доступным для следственных действий.

В ответах сценария можно узнать о скрытых персонажах.

Персонажи в сценарии должны описываться таким образом, чтобы это описание помогло детективам в расследовании.

== Движения и действия персонажа

Механика разделяет понятия *перемещение* и *действие*.
Для каждого персонажа в течение преступления *в каждый такт* времени Ti есть только одна из следующих альтернатив:

* Остаться в текущей локации и ничего не делать.
* Остаться в текущей локации и далее выполнить *одно* *действие*.
* Переместиться в соседнюю локацию и ничего не делать.
* Переместиться в соседнюю локацию и далее выполнить одно *действие*.

Перемещение происходит в соседнюю локацию, если они соединены *путём*.  
Со стороны сценария возможны какие-либо ограничения на путь, например, дверь, которую нужно открыть ключом (задаётся в описании пути).  
В общем случае персонаж может посещать одну и ту же локацию несколько раз в разных тактах.  
Для более лёгких вариантов игры персонаж может посетить локацию только один раз.

Трек движения персонажа (последовательность локаций) подразумевается сценарием, но игрокам явно не раскрывается.  
Игроки могут определить этот трек при расследовании.

Треки персонажей раскрываются сценарием как «ответы»: для каждого персонажа обозначены его перемещения в виде последовательности ID локаций для каждого такта (в журнале персонажа).  
Эту информацию можно посмотреть в конце игры.

Во время фазы расследования для визуализации предполагаемого пути (*трека*) движения персонажа по игровому полю могут быть использованы различные способы — жетоны, выкладываемые на локации, записи на бумаге и т. п.

При нахождении в *целевой* локации персонаж может выполнить какое-либо *одно* действие. Само действие как сущность механика не предусматривает, но результатом этого действия становятся *улики* (одна или несколько), которые связываются с локацией, с персонажами, с экспертизой.

==== 
Например: 

* Персонаж увидел где-то другого персонажа. У первого персонажа появляется улика в виде свидетельского показания, которую можно выявить при допросе.

* Один персонаж убил другого персонажа. У убитого персонажа появляется улика — «Персонаж мёртв». У убийцы — «Следы крови на одежде».
====

Сценарий для каждого персонажа описывает журнал событий (log) этого персонажа для каждого такта времени.  
В событии лога содержится информация о том, в какой *целевой* локации находился персонаж и какие улики были привязаны к нему (например, оставил след в локации или на персонаже остался след, оставил предмет в локации и т.п.).

Журнал событий используется в конце игры при проверке выводов следствия и недоступен игрокам в процессе следствия.

== Улики

*Улика* (clue) — часть сведений о совершённом преступлении, которые последовательно обнаруживают детективы при расследовании.  
Уликой может быть какой-либо физический предмет, событие, какая-то информация, факт.

Примеры улик: свидетельское показание, мотив, записка, окурок, привычка, пристрастие персонажа, факт отсутствия предмета в локации, экспертное заключение.

Сценарий преступления определяет набор улик, участвующих в игре.  
Улика представлена картой улики с напечатанным на ней:

* ID;
* Название;
* Описание (детальное);
* Изображение улики.

По возможности улики не должны прямо указывать на подозреваемого — связка должна вырисовываться при сопоставлении с другими сущностями. Это усложняет задачу детективам. В сценарии, в качестве ответов для проверки результатов следствия, для каждой улики можно указать фактические сущности, к которым ведёт (leads) данная улика.

Некоторые из улик могут не иметь отношения к преступлению и служить для того, чтобы усложнить игру (ложные, falsity улики). Чем больше таких улик, тем сложнее игра.

Изначально в общем случае улики скрыты от детективов.  
В процессе расследования детективы постепенно «открывают» улики — выкладывают в открытую карты улик. Однако часть улик сценарий может пометить как изначально открытые (discovered) и доступные детективам.

Любая улика может при своём открытии автоматически открывать (uncover) другие сущности — скрытые локации/персонажей, другие улики. Возможность автооткрытия для улики определяется сценарием.

В процессе преступления улики появляются как результат действия персонажей либо внешних факторов. 

====
Например:
 
* Из-за отключения электричества в такт T5 в локации L4 появляется улика «В локации темно», что фиксируется в журнале локации.
* В какой-то момент в локации появился ядовитый газ. В результате у персонажа появляется улика-показание «В L9 в T9 я почувствовал, что теряю сознание».

====

Источниками улик для детективов являются:

* Локации
* Персонажи
* Экспертиза

Одна и та же улика сценарием может быть привязана к разным источникам (и соответственно сущностям).

====
Например, улика-факт *CSAF* («Вскрытый сейф») может быть получена детективами из разных источников:

* *Локация (Обыск):* при осмотре Кабинета (*L1*), если детективы целенаправленно ищут следы взлома.
* *Персонаж (Допрос):* при допросе Охранника (*P2*) с фокусом на Кабинет (*L1*) и время (*T3*), если он заметил взлом во время обхода и сообщает об этом следствию.
* *Экспертиза:* при исследовании найденной в коридоре отмычки (*CTOL*).

Как только улика *CSAF* открыта любым из способов, мастер-программа исключает её из остальных источников.
====

Множественную привязку к источникам следует использовать осмотрительно, чтобы избежать двусмысленности для детективов при расследовании.

=== Улики локаций

В процессе преступления часть улик остаётся в локациях. Детективы при расследовании могут их там обнаружить при проведении обыска. 

====

Примеры улик в локации:

* Скрытый проход в локацию L4 (Подвал)
* Здесь отсутствует C2 (Подсвечник), хотя изначально был тут
* Сломанные часы. Стрелка показывает на 10:30 (T8)
* Здесь был замечен персонаж P1 (Садовник) в 10:30 (T3) с Ножом (CKNF) в руке
* Здесь темно

====

=== Улики персонажей

У персонажей, так же как и у локаций, могут находиться некоторые улики.  
Считается, что часть из них была у персонажа до преступления, например — одежда, личные вещи, характер.  

Часть улик персонажи получили во время преступления — подобрали в локациях или получили от других персонажей, например — нож, записка, следы крови.  

Другая часть описывает их неотъемлемые черты. Например — привычки, пристрастие к алкоголю, характер и т. п. 

Остальная часть улик — свидетельские показания персонажа: где-то что-то слышал, видел, знает о и т. п.  

Сценарий также предполагает, что в процессе преступления персонажи могут оставлять улики в локациях, передавать или подкидывать другим персонажам при встрече с ними в одной локации.

Часть улик персонажа может быть известна детективам до расследования, например — одежда, характер и т. п. Другая часть улик — скрыта.

====

Примеры улик у персонажа:

* Находясь в Библиотеке (L1) видел Дворника (P1) в саду (L4) 
* Почувствовал запах гари со стороны Лагеря (L3)
* У меня скверный характер и я люблю курить
* Перочинный нож со следами грязи

====

== Обыск локации или персонажа (search)

При проведении расследования детективы могут *«обыскать»* любую открытую локацию или персонажа (в том числе и ранее скрытые), чтобы попытаться открыть эти улики.

В результате обыска с некоторой вероятностью может быть «обнаружена» (открыта) улика.

Для начального описания картины преступления часть улик в локациях или у персонажей может быть известна детективам до расследования. 
Остальная часть улик — скрыта.

====
Например:

* В локации библиотека — открытая улика: «Взломанный сейф».
* У персонажа PVIC открыта улика — «Персонаж мёртв».
====

Для определения параметров открытия улик при обыске сценарий задаёт таблицу *«Обыск»* (search).  

Обыск реализуется через механику вероятностного обнаружения улик вместе с механикой *«Фокус обыска»*.  

Фокус позволяет с большей вероятностью обнаружить улику, на которую направлен фокус обыска, и получить детективу больше очков.  
Однако стратегическая цель фокуса — больше не «получить» улику, а скорее *сформулировать гипотезу для проверки*.  
Фокус состоит из двух частей: табличный фокус (референсный) и фокус детектива.

Обыск стоит определённого ресурса. За обыск детективу могут быть начислены очки.

Процедура обыска:

1. Детектив заявляет о проведении обыска конкретной локации или персонажа, например L1.
2. Указывает фокус детектива — набор ID любых *открытых* сущностей или любых типов сущностей, кол-вом не более заданного в сценарии (лимит фокуса).
+
Например: T4, L?, C?.
3. Кидает дайс D12 для моделирования вероятностного характера обнаружения улики.
4. По таблице «Обыск» определяется результат обыска.  
   Доступ к таблице обыска осуществляется через мастер-программу.


=== Пример таблицы «Обыск»

|===
|Фокус           |Порог|Улика
| P4, L3, L4, T4 |5.2  |C8
| L4, C5, C6     |5.0  |C3
|     L6         |8.0  |C12
|===

----
Улика C8 привязана сценарием к персонажу P1, а C3 и C12 к локации L1.
----

[[search-focus]]  
*Фокус* — табличный фокус обыска. Служит для повышения вероятности открытия улик, имеющих связи с целевыми сущностями, интересующими детектива.  
В табличном фокусе перечисляются только _ID_ сущностей, связанных с целевой уликой.  
Указание отдельных типов сущностей в табличном фокусе не допускается.  
Можно через запятую перечислить несколько ID одинакового типа — это трактуется как любой из них.

Фокус детектива может состоять из одного или нескольких ID *открытых* сущностей или любых типов этих сущностей.  
Например: «P1, C1, T?». Максимальное количество элементов в фокусе детектива определяется в сценарии (обычно 1–3).

*Порог* — порог обнаружения улики. _Действительное_ число, которое сравнивается с выпавшим на дайсе D12.  
Если выпало меньше «Порога», считается, что сыграли негативные факторы, и целевая улика не обнаружена.  
В сценарии порог обнаружения задаётся таким образом, чтобы наиболее важные для следствия улики имели большие значения порогов. Возможность указания дробных значений позволяет «тонко» упорядочить улики.

Для уменьшения влияния случайности нужно указывать малые значения порогов; для исключения случайности — меньше 1.

*Улика* — ID целевой улики. Карта обнаруженной улики выкладывается в открытую рядом с той сущностью, у которой она обнаружена.

=== Стоимость обыска, начисление очков

[[search-cost]]  
*Стоимость обыска* — ресурсная стоимость обыска для любых сущностей одинакова и определяется в сценарии.  
Определяет, сколько ресурсов тратится за обыск. Стоимость детектив узнаёт в начале игры.

[[search-points]]  
*Очки за обыск* — базовое количество очков, которые могут быть начислены детективу за обыск.  
Для всех сущностей в сценарии определяется одинаковое базовое количество очков.  
Базовые очки начисляются за открытие улики, но только если она _НЕ_ была *<<accidental-discovery, случайно обнаружена>>*.  
При начислении базовых очков дополнительно к ним начисляется по одному очку за каждое совпадение _id сущности_ в фокусе детектива с табличным.

== Алгоритм определения целевой улики в таблице обыска

Цель алгоритма: определить улику, наиболее соответствующую фокусу детектива и броску D12.

В алгоритме рассматриваются только строки таблицы обыска, относящиеся к выбранной сущности.  
Из рассмотрения исключаются строки, для которых улика уже была ранее открыта.

1. Бюджет расследования уменьшается на величину стоимости обыска.
2. Если для выбранной сущности таблица обыска пустая - сообщается 
что улики для данного источника исчерпаны. Сущность помечается как недоступная более для обыска (например на нее выкладывается жетон "Обыск недоступен"). Алгоритм завершается.
3. Для каждой строки вычисляются веса фокуса EQ, EQT, NE (см. <<focus-weights-comp, вычисление весов соответствия фокусов>>).
4. Строки таблицы упорядочиваются по убыванию «EQ», убыванию «EQT», возрастанию «NE», убыванию *Порога*, порядку перечисления в сценарии.
5. Последовательно, начиная с первой строки, идёт «просмотр» строк.
6. Если (D12 >= «Порог») и ( EQ > 0 или EQT > 0 ), просмотр останавливается. Улика обнаружена целенаправленно, она открывается.  
+
Сообщается, сколько очков начислено детективу.
+
Сообщается о соответствии _фокуса детектива_ с табличным фокусом открытой улики:

   * Совпавшие ID и типы сущностей из фокуса детектива;
   * Не совпавшие с фокусом детектива _типы_ сущностей из _табличного_ фокуса.

====
Например, при обыске L1 для фокуса детектива «P2, T4, C?» и табличного фокуса «P1, P2, T4, L2» будет выведено:  
«В L1 была найдена улика C2, связанная с P2, T4, P?, L?».
====

[start=7]
[[accidental-discovery]]  
7. Если подходящей строки не найдено (фокус не соответствует или значение D12 недостаточно), происходит *«Случайное обнаружение»* улики.  
Открывается улика с самым низким порогом среди рассматриваемых (ещё не открытых улик).  
+
Сообщается, что случайно обнаружена подозрительная улика без дополнительной информации, как в случае с целенаправленным обнаружением.


[[focus-weights-comp]]  
=== Вычисление весов соответствия фокусов

Вычисляются следующие значения весов соответствия фокусов детектива и табличного фокуса:

* EQ = количество совпавших ID сущностей в фокусах,
* EQT = количество совпавших типов в фокусах,
* NE = количество *НЕ* совпавших сущностей или типов в фокусе обыска детектива и в табличном фокусе.

1. Формируется множество U как _пересечение_ множеств ID сущностей в фокусе детектива и табличном. 
2. EQ принимается равным количеству элементов в U. 
3. Из обоих фокусов удаляются ID сущностей которые есть в U.
4. Формируется множество T содержащее уникальные типы сущностей из оставшихся в табличном фокусе ID элементов. 
5. Формируется множество V как _пересечение_ множества типов сущностей в фокусе детектива (P?, L?, …) и множества T.
6. EQT принимается равным количеству элементов в V. 
7. Из фокуса детектива исключаются типы сущностей которые есть в V а из табличного фокуса ID сущностей с типами которые есть в V
8. NE принимается равным общему кол-ву оставшихся элементов в фокусе детектива и табличном фокусе.

====

Например:
* Фокус детектива P1, T?, L?, P?, C2
* Табличный фокус P1, P2, P3, T4, C1  

EQ = 1 (для P1), EQT = 2 (для T? ~ T4; P? ~ P2,P3), NE = 3 (для L?, C1, C2).

====

[[interrogation]]  
== Допрос персонажа (interrogation)

Помимо обыска любого открытого персонажа, для получения улик детектив также может его *допросить*. Результатом допроса могут быть не только свидетельские показания, но и физические улики — считается, что в результате допроса персонаж передал что-то детективу.

Во время допроса детектив «спрашивает» персонажа об *известных* следствию фактах (*открытых* ключевых сущностях) или о гипотезах следствия (о любых типах сущностей) — то есть определяет *фокус допроса* детектива.  
Если персонажу «известно» что-либо об этом, открывается связанная с фокусом улика.

Механика допроса построена таким образом, чтобы детективу без знания ключевых сущностей или их типов было затруднительно открыть релевантную целевую улику.

При ответе персонаж может *«сказать неправду»* — открывается улика, которая на самом деле никак не связана с ключевыми сущностями в фокусе допроса (*ложная*, falsity улика). Сценарий регулирует количество «ложных» улик. Ложность улики может быть установлена только при дедуктивном анализе.  
В ответах сценария перечисляются, какие улики были действительно ложными.

Каждый персонаж в той или иной степени не желает делиться определённой информацией, а детектив использует психологическое давление, чтобы получить максимум информации.  
Это взаимодействие имеет случайный характер и моделируется с помощью броска D12.

Допрос персонажа стоит определённого ресурса. За допрос детективу могут быть начислены очки.

Сценарий задаёт таблицу связей *«Допрос»* (interrogation), которая определяет параметры открытия улик при допросе.

Процедура допроса:

1. Детектив на основе известных ему из хода расследования улик и логических заключений выбирает персонажа, которого нужно допросить, например P1.
2. Указывает фокус детектива — набор ID любых *открытых* сущностей или любых типов, например L1, P?.
3. Бросает D12 для моделирования психологического давления на персонажа.
4. По таблице допроса определяется результат допроса.  
   Доступ к таблице допроса осуществляется через мастер-программу.

=== Пример таблицы «Допрос»

|===
|Фокус             |Порог |Улика
|P2, L3, C4, C5, T2| 3.0  |C3
|C4, T5, T6        | 5.0  |C12
|P5                | 5.2  |C15
|===

----
  Улика C3 связана с персонажем P4, а C12/15 — с P1.
----

*Фокус* — табличный фокус допроса (то же, что и <<search-focus, табличный фокус обыска>>).

====
На фокус детектива налагается ограничение:  

*Среди элементов фокуса детектива обязательно должен быть как минимум один ID открытой сущности.*
====

*Порог* — порог сопротивления психологическому давлению детектива.  
_Действительное_ число, которое сравнивается с выпавшим на дайсе D12.  
Если выпало меньше «Порога», считается, что детектив не смог преодолеть нежелание персонажа делиться информацией, и поэтому целевая улика не открывается.  
В сценарии порог обнаружения задаётся таким образом, чтобы наиболее важные для следствия улики имели большие значения порогов. Возможность указания дробных значений позволяет «тонко» упорядочить улики.

Для уменьшения влияния случайности нужно указывать малые значения порогов; для исключения случайности — меньше 1.

*Улика* — целевая улика персонажа, которая открывается при успешном допросе.  
Улика может быть задана сценарием преднамеренно ложная — имитация того, что персонаж лжёт / забыл.

=== Стоимость допроса, начисляемые очки

*Стоимость допроса* — ресурсная стоимость допроса любых персонажей одинакова и определяется в сценарии.  
Определяет, сколько тратится ресурса за допрос персонажа. Детектив узнаёт стоимость в начале игры.

*Очки за допрос* — базовое количество очков, которые могут быть начислены детективу за допрос персонажа.  
Для всех персонажей в сценарии определяется одинаковое базовое количество очков.  
Базовые очки начисляются за открытие целевой улики при допросе (ложной или нет).  
При начислении базовых очков (если улика открывается) дополнительно начисляется по одному очку за каждое совпадение _сущности_ в фокусе.

[[interrogation-alg]]  
=== Алгоритм определения целевой улики в таблице допроса персонажа

Алгоритм определения целевой улики преследует следующую цель: определить улику персонажа, максимально соответствующую фокусу детектива, но при этом улики должны раскрываться начиная с наименее значимой для расследования.

В алгоритме рассматриваются строки таблицы допроса, относящиеся к выбранному персонажу.  
Из рассмотрения исключаются строки, для которых улика уже была открыта в предыдущих допросах.

1. Бюджет расследования уменьшается на величину стоимости допроса.
2. Если для выбранного персонажа таблица допроса пустая - сообщается 
что улики для допроса у данного персонажа исчерпаны. Персонаж помечается как недоступный более для допроса (например на его карту выкладывается жетон "Допрос недоступен"). Алгоритм завершается.
3. Для каждой строки вычисляются веса фокуса EQ, EQT, NE (см. <<focus-weights-comp, вычисление весов соответствия фокусов>>).
4. Строки таблицы упорядочиваются по убыванию «EQ», убыванию «EQT», возрастанию «NE», возрастанию *Порога*, порядку перечисления в сценарии. Выбирается первая строка.
5. Если для этой строки «EQ = 0», персонаж не знает, о чём спрашивает детектив. Целевая улика не открывается. Допрос считается не продуктивным.
   Сообщается о том, что у персонажа нет нужной информации:

   * Все ID из фокуса детектива  (как несовпавшие)
   * Совпавшие с табличным фокусом  _типы_ сущностей из фокуса детектива;
   
====
Например, для фокуса детектива «L3, P?, T?» и табличного фокуса «L4, P1, C2» будет выведено:  
«Персонаж P1 не знает о L3, но упомянул о P?».
====

Алгоритм завершается.

[start=6]
6. Если «EQ > 0», персонаж знает, о чём спрашивает детектив. 
   Для сообщения выбираются:

   * Совпавшие ID и типы сущностей из фокуса детектива;
   * Не совпавшие с фокусом детектива _типы_ сущностей из _табличного_ фокуса.

Далее выполняется пункт 7 или 8 в зависимости от D12 и порога.

7. Если «D12 >= Порог» - считается, что детектив преодалел сопротивление персонажа. Открывается целевая улика, допрос успешен. Сообщается об открытии улики и связях (п.6):

====
Например, для целевой улики C8, фокуса детектива «L3, P?, C?» и табличного фокуса «L3, P7, P4, T2» будет выведено:  

«Персонаж P1 знает о L3, P?, T?, связанных с C8».  
====

Детективу начисляются очки, сообщается, сколько начислено.
Строка, соответствующая целевой улике, исключается из дальнейших допросов.  

[start=8]   
8. Если «D12 < Порог», целевая улика не открывается. Сичтается что детектив не смог убедить персонажа полностью раскрыть информацию. Сообщается лишь о связях (п.6):  

====
«Персонаж P1 знает о L3, P?, T?, но не захотел делиться деталями».
====

== Экспертиза (examination)

Экспертиза — это любое процессуальное действие по установлению связей между *открытыми* сущностями, у которых нет прямых отсылок друг на друга. Например: определить, соответствует ли пепел, найденный в локации, сигаретам, найденным у персонажа; провести баллистическую экспертизу; взломать цифровой носитель и т. п.

При проведении экспертизы существуют случайные факторы, которые влияют на её результат.  
Это влияние моделируется броском D12.

Экспертиза стоит определённого ресурса. За экспертизу детективу могут быть начислены очки.

Сценарий задаёт таблицу связей *«Экспертиза»*, которая определяет связь между сущностями.

Процедура проведения экспертизы:

1. Детектив указывает фокус детектива — набор ID любых *открытых* сущностей или любых типов, например C1, P?.
2. Бросает дайс D12 для моделирования влияния случайных факторов.
3. По таблице «Экспертиза» определяется результат экспертизы.  
   Эта таблица доступна только через мастер-программу.
4. По завершении экспертизы заполняется карточка «Экспертное заключение», в которой указываются результаты экспертизы.

=== Таблица связей «Экспертиза»

|===
|Фокус          |Порог|Улика
| P2, L3, L5, T6|10.0 | C2
| P3, C3, C4    |7.1  | C4
|===

*Фокус* — табличный фокус экспертизы (то же, что и <<search-focus, табличный фокус обыска>>).

====
На фокус детектива налагается ограничение:  

*Среди элементов фокуса детектива обязательно должны быть как минимум два ID открытых сущностей.*
====

*Порог* — порог влияния случайных факторов на экспертизу.  
_Действительное_ число, которое сравнивается с выпавшим на дайсе D12.  
Если выпало меньше числа «Порога», считается, что негативное влияние факторов существенное, экспертиза проведена некачественно, и целевая улика не открывается.  
В сценарии порог влияния задаётся таким образом, чтобы наиболее важные для следствия улики имели большие значения порогов. Возможность указания дробных значений позволяет «тонко» упорядочить улики.

Для уменьшения влияния случайности нужно указывать малые значения порогов; для исключения случайности — меньше 1.

*Улика* — целевая улика, по сути — экспертное заключение, детализирующее связь.  
Например: «Обнаруженные отпечатки пальцев совпадают».

=== Стоимость экспертизы, начисляемые очки

*Стоимость экспертизы* — ресурсная стоимость любой экспертизы одинакова и определяется в сценарии.  
Определяет, сколько тратится ресурса за проведение экспертизы. Детектив узнаёт стоимость в начале игры.

*Очки за экспертизу* — базовое количество очков, которые могут быть начислены детективу за экспертизу.  
Для всех экспертиз в сценарии определяется одинаковое базовое количество очков.  
Базовые очки начисляются детективу за открытие улики.  
При начислении базовых очков (при открытии улики) дополнительно начисляется по одному очку за каждое совпадение _сущности_ в фокусе.

== Алгоритм выявления строки связи в таблице экспертизы

Алгоритм определения связи преследует следующую цель: определить наличие связи и дополнительных данных для сущностей, максимально соответствующих фокусу детектива и броску D12.

Из рассмотрения исключаются строки, для которых в предыдущих экспертизах была открыта целевая улика.

[[expertise-quality]] 
1. Бюджет расследования уменьшается на величину стоимости экспертизы.
2. Если таблица экспертизы пустая - сообщается что улики для экспертизы исчерпаны. Экспертиза помечается как недоступный более для получения улик источник (например выкладывается жетон "Экспертиза недоступна"). Алгоритм завершается. 
3. Для каждой строки вычисляются веса фокуса EQ, EQT, NE (см. <<focus-weights-comp, вычисление весов соответствия фокусов>>).
4. Строки таблицы упорядочиваются по убыванию «EQ», убыванию «EQT», возрастанию «NE», возрастанию *Порога*, порядку перечисления в сценарии. Выбирается первая строка.
5. Если «EQ = 0», связи не выявлены. Целевая улика не открывается.  
Сообщается о невыявлении связи:
  
   * Все ID из фокуса детектива  (как несовпавшие)
  
====
Например: «Связь между L2, P4 не выявлена».
====

Алгоритм завершается.

[start=6]
6. Если «EQ = 1», выявлены связи для одной сущности. Целевая улика не открывается. Сообщается о связях «в общем»:

   * Совпавшие с табличным фокусом _типы и ID_ сущностей из фокуса _детектива_;

====
Например, для фокуса детектива «L2, L3, P?» и табличного «L2, L4, P1, T3»:  

«Выявлена связь L2 c P?» или «Выявлена связь L2 c сущностями» 
====

Алгоритм завершается.

[start=7]
7. Если «EQ > 1», связь обнаружена.  
Для сообщения подготавливаются:

   * Совпавшие с табличным фокусом _типы и ID_ сущностей из фокуса _детектива_;
   * Не совпавшие с фокусом детектива _типы_ сущностей из _табличного_ фокуса.

Далее выполняется пункт 8 или 9 в зависимости от D12 и порога.

[start=8]
8. Если «D12 >= Порог», влияние случайных факторов на экспертизу низкое, целевая улика открывается, сообщается об открытии улики и связях.  

====
Например для фокуса детектива «L2, L4, P?» и табличного «L2, L4, L5, P1, T3»  
 
Заключение экспертизы: «Обнаружена связь между L2, P4, L?, T?, P?. Заключение экспертизы C3».  
====

Сообщается, сколько очков начислено детективу.

Строка с открытой уликой исключается из дальнейших экспертиз.  

[start=7]
7. Если D12 < Порог, влияние факторов высокое, целевая улика не открывается.  

====   
Сообщается: «Обнаружена связь L2, P4 с L?, T?, P?. Проведение экспертизы было затруднено».
====

== Статистики фокуса

Получение статистики табличных фокусов является опциональной механикой; возможность использования регулируется в сценарии.  
Получение статистики может быть разрешено для уменьшения сложности игры для новичков.

Получение статистики фокуса может быть как бесплатным, так и стоить определённого ресурса (обозначается в сценарии).

Статистика вычисляется на момент её запроса — в учёт не берутся строки, для которых уже открыты целевые улики.

[[location-glue-hint]]  
=== Статистика обыска

Перед проведением обыска детектив может запросить текущую статистику обыска:

1. Вычисляется процент каждого из типов сущностей во всех табличных фокусах обыска.
2. Выдаётся статистика: «Возможные связи сущности с P 45%, L 30%, T 25%, C 0%».

[[personage-glue-hint]]  
=== Статистика допроса

Перед проведением допроса детектив может запросить текущую статистику допроса:

1. Вычисляется процент каждого из типов сущностей во всех табличных фокусах допроса.
2. Выдаётся статистика: «Персонаж может знать о P 45%, L 30%, T 25%, C 0%».

[[expertise-glue-hint]]  
=== Статистика экспертизы

Перед проведением экспертизы детектив может запросить текущую статистику экспертизы:

1. Вычисляется процент каждого из типов сущностей во всех табличных фокусах экспертизы.
2. Выдаётся статистика: «Экспертиза может определить связи между P 45%, L 30%, T 25%, C 0%».

== Регулирование влияния случайности

Для уменьшения влияния фактора случайности (D12) игроки при запуске сценария в мастер-программе могут указать фактор влияния случайности (rand factor). Это коэффициент, принимающий значения от 0.0 до 1.0, на который умножаются табличные пороги открытия улик. 

При значении 0.0 фактор случайности полностью нивелируется. При значении 1.0 фактор случайности остаётся на уровне сценарной задумки.

== Баланс механик обыска, допроса и экспертизы

Обыск всегда даёт улику: при провале броска срабатывает «Случайное обнаружение» и открывается улика с наименьшим порогом. Допрос и экспертиза при провале не открывают улику. Если обыск дешевле и ключевые улики выдаёт он, возможно, выгодно сначала обыскать всё, а допрос/экспертиза могут обесцениться. Чтобы избежать подобного дисбаланса механики, нужно выставить параметры сценария следующим образом: обыск не должен быть самым дешёвым источником ключевых улик; допрос и экспертиза должны быть конкурентоспособны по стоимости; бюджет не должен позволять обыскать всё с запасом на допросы; ключевые ID распределяются между действиями; в локациях размещаются ложные улики с низкими порогами, чтобы случайное обнаружение выдавало «шум» или малозначимые улики.

== Переиспользование сущностей, референсные и кастомные сущности

Сценарий может использовать некоторые сущности из других (*референсных*) сценариев.
Для этого в сценарии перечисляются эти сущности в том виде, в котором они определены в референсном сценарии (как обычные сущности сценария), с пометкой, из какого сценария они заимствованы.  
Такие сущности называются *референсными*.

Все сущности сценария, не являющиеся референсными, считаются *кастомными сущностями* (локальными сущностями сценария) и печатаются перед началом игры.
Карточки референсных сущностей берутся из референсных сценариев (если они были напечатаны ранее) либо также печатаются.

== Переиспользование изображений сущностей

В сценарии для переиспользования изображений сущностей (чаще всего улик, свидетельских показаний и выводов экспертизы) для каждой сущности можно указать ID сущности, изображение которой будет использовано для данной сущности (ассет).

== Ответы

После завершения расследования детективы формулируют выводы. 
Далее с помощью мастер-программы отображаются «ответы» из сценария.

====
 Например:
 
* Фабула преступления;
* Логи персонажей/локаций;
* На что в действительности указывают (leads) конкретные улики;
* Скрытые локации, пути, персонажи.   
====

Выводы следствия сравниваются с ответами. Принимается решение об успешности расследования.
